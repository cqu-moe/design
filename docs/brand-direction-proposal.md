# CQU Moe 统一品牌方向 · 决策与迁移记录

日期：2026-10-20；蓝色确认：2026-10-21。此文记录讨论、原型与迁移进度；正式规则见 DESIGN.md、docs/brand.md 和 docs/product-pages.md。theme / ui 源码基线为 1.2.0，尚未发布。

## 已确认与待选

用户已确认：

- 全产品统一使用蓝色（2026-10-21 已确认），不再沿用逐产品配色。
- favicon、扩展工具栏、应用图标一并统一颜色，产品由独立图形与名称区分。
- 工作界面保留黑白主按钮；Logo、链接与焦点可以少量使用品牌色。
- 按操作目的区分页面。登录、授权、首次配置按工作界面处理；介绍价值的区域才增强品牌表达。

仍待选择：展示页的首选版式。蓝色已选定，原型移除青绿和暖橙切换；当前蓝色色阶见 docs/tokens.md，已经成为共享主题 API。

## 建议落地规则

| 层面       | 统一内容                                             | 允许变化                               |
| ---------- | ---------------------------------------------------- | -------------------------------------- |
| 品牌身份   | 一种品牌色、共同的图形语言、产品命名和字标关系       | 每个产品的图形轮廓与产品名             |
| 展示页     | 同一套色阶、文字与控件规则                           | 色面面积、标题编排、产品图形与产品演示 |
| 工作界面   | 中性背景、石墨灰深色表面、黑白主按钮、灰色导航选中态 | 任务所需的信息密度与页面组合           |
| 状态与数据 | 成功、警告、错误的语义；颜色同时配文字或图形         | 多系列图表、课表分类等有信息含义的颜色 |

统一品牌色不意味着所有像素都用同一个色值。同色相需要适应浅深背景、正文、实色底和悬停状态。验收以实际背景上的可读性和辨识度为准，不制定“颜色必须占页面百分之几”的机械指标。

展示页可以有大色面，但不要求每个区块都鲜艳；工作界面的卡片、侧栏、表格、状态统计不因品牌统一而整体染色。尤其不要把成功状态、警告和危险操作改成品牌色。

Logo 保留现有「通路」轮廓和留白。统一颜色后，必须单独检查 16 / 24 / 32px 的黑白轮廓和同色并列辨识度；如果小尺寸难以区分，再修订小尺寸标识，而不是重新引入产品专属颜色。

## 原型

启动：首次安装后 `pnpm build`，然后 `pnpm --filter @cqu-moe/preview exec vite --host 127.0.0.1 --port 5188`。

入口：<http://127.0.0.1:5188/prototypes/brand-direction/>。开发服务器提供独立 HTML 入口，正式 router 不引用原型，默认生产构建不输出这个入口。

首轮「色面 / 图形 / 排版」已被用户否决：通用卖点与假设备列表掩盖了真实用途，产品页缺少安装条件、操作方式、功能边界和支持入口。该轮截图和检查不能作为新版验收。

第二轮比较的是首屏组织方式；下方的完整产品信息在三个方向中保持一致：

| 方向 | 比较轴                           | 适用与成本                                       |
| ---- | -------------------------------- | ------------------------------------------------ |
| 分区 | 左侧价值说明，右侧可操作演示     | 阅读与体验并列；首屏空间较充裕                   |
| 手册 | 左侧品牌说明，右侧使用条件与演示 | 更突出安装前提，宋体标题更像说明册；纵向空间更多 |
| 演示 | 蓝色标题与会话关系并列           | 首屏同时解释价值与同步关系；完整安装说明在下方 |

2026-10-21 用户提供 [Diolen](https://diolen.pages.dev/) 作为视觉参照。实际观察了其首屏与下方说明：借鉴标题分量、统一色调、左右内容关系和与产品有关的实体展示。第三版改为蓝色标题、安装动作与会话演示并列，QuickLogin 用 Auth 到浏览器的关系说明同步范围；未照搬绿色配色、尺子图形或娱乐文案。展示页仍待用户视觉确认。

原型只保留 QuickLogin 与快速评教两个内容已核实的试点，删除内容空泛的 Schedule / Feed 占位页。可切换浅深外观和工作界面。底部选项或 1–3、左右键切换方向。配色固定为用户选定的蓝色。

用户进一步指出快速评教的绿色演示框仍不好看。随后移除大面积深绿底、白色大切换按钮、缩小截图与重复流程说明；改为浅品牌衬底、单层中性演示窗口、细线步骤栏和 16px 可操作表单。示例填写、勾选课程、预览完成状态均只在内存中运行。它是重新编排的设计示例，不是现有脚本已经改版的证据。

快速评教已从本地主仓库 `c2bccbb` 导入批准的路径、参考稿和提取记录，并纳入正式品牌生成器。原型直接读取 `/brand/jxzljc/logo-black.svg` 的轮廓，移除了临时快照；七个产品轮廓均与批准源逐字段核对。

## 最小实施顺序

1. **用原型选择展示方式；蓝色已确认。** 至少比较 QuickLogin 和快速评教的首页、工作界面、浅深模式与手机布局；保留被否定方向的理由。
2. **在 design 固化规则与素材。** 已同步规则、四个共享品牌 token、七个产品素材、正式预览与模板。单一品牌色与图形区分产品的决策集中记录在 brand.md；消费者迁移另外执行。
3. **让共享主题提供品牌语义。** 建议最低限度增加实色底、底上文字、品牌文字、浅品牌面四个角色；工作界面的 `--primary` 仍为黑白，链接与焦点映射到品牌文字角色。展示页局部绑定主动作；不要在根级把 `--primary` 一律改成彩色，也不增加可任意传 hue 的产品主题 API。
4. **重建品牌产物，再试点两个产品。** 同步 SVG、favicon、触屏图标、扩展各尺寸图标和品牌包哈希。QuickLogin 与快速评教分别覆盖扩展和用户脚本两种消费方式。官网、弹窗、官网中的弹窗预览、脚本内嵌样式都属于验收面。
5. **试点通过后逐个迁移其余产品。** CQU Moe 主站、Schedule、Auth、Feed、Learning 的图形复用与颜色入口分别核对。迁移视觉，不夹带业务重构。

共享主题增加兼容 token 时按当前策略同步升级 theme / ui minor 版本，并更新模板、锁文件与随包文档。正式版本在落地时按最新基线决定。品牌资产独立发布，不能只升级 CSS 而漏掉 favicon 和扩展图标。

## 验收与治理

- 设计仓库：正式变更按 maintenance.md 运行 check、test:e2e、verify:consumer；包、模板、文档与预览一致。
- 视觉：320 / 390 / 768 / 1440、浅深主题；正文与按钮文字对比度；Logo 小尺寸；焦点、触屏、减少动态效果。
- 消费项目：各自构建、主题／品牌同步校验与交互测试；使用合成数据检查界面，不访问真实课程和账号。
- 发布：源码与本地截图、CI、站点部署、实际扩展升级、商店发布分别记录。不得把素材同步当成产品已上线。
- 防止漂移：新项目复用正式角色与页面模板；不新增产品专属品牌色；确有业务信息意义的颜色按语义审查。共享检查可发现硬编码，不能代替人工审查。

本节描述选色阶段的 1.1.0 历史状态；当前 design 已新增共享 token 与蓝色素材，基线升为 1.2.0。尚未发布包、同步业务仓库、提交 PR 或部署站点。
