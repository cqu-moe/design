# 设计系统问题反馈约定

子系统开发 Agent 发现共享组件、模板或示例的缺陷、缺失能力或改进机会时，必须在交付中提醒用户；阻塞功能时及时说明，不等到最后。

## 先复现，再决定去向

1. 记录 @cqu-moe/ui / theme / lucide-react 版本、系统、浏览器、视口、主题和输入方式。
2. 用公开 API 在最小页面复现，确认不是业务 CSS 覆盖、错误导入、重复 Provider 或接口失败。
3. 查本版本类型和示例。能用现有组件组合解决的业务需求留在子系统；通用缺陷或能力缺口反馈给设计系统。
4. 默认把下面的记录交给用户。**只有用户明确授权创建 issue 且给出对应仓库时**，才检查该仓库已有 issue 并创建或补充，完成后返回链接。

目前没有配置设计系统远程仓库或 issue 地址；不能猜测仓库、自行发布，或把普通“继续开发”视为创建 issue 的授权。

## 可复制记录

```md
标题：[组件/模板/示例] 简述问题
类型：缺陷 / 能力缺口 / 改进
版本：ui / theme / lucide-react
环境：系统、浏览器版本、视口、主题、键盘或触屏
最小复现：页面路径、代码片段、操作步骤、脱敏截图
实际表现：具体发生什么
预期表现：应如何工作；引用现行规范或业务需求
影响范围：受影响页面/用户，是否阻塞，是否仅某主题/设备
建议：最小修复或可复用的公开 API；可选替代方案
临时处理：是否采用、限制、移除条件
验证：已执行检查与未覆盖事项
相关 issue：已有链接或“尚未创建，待授权与仓库地址”
```

不得上传令牌、Cookie、密码、真实学生资料或未脱敏日志。反馈中代码保留最小场景，不上传整个业务数据集。

## 防止分叉

- 不把共享组件源码复制到业务仓库后修改，也不覆盖 .ds-* 内部选择器、patch node_modules 或私建不同名字的同功能组件。
- 临时方案优先组合现有 API；写明限制、关联反馈和移除条件。涉及共享行为的修改由设计系统仓库统一完成并发布新版本。
- 维护者在 issue/修复说明中给出影响范围、回归验证和升级方式；子系统升级同版本的两个包与锁文件，验证后删除临时方案。
- 没有授权或仓库地址时继续非阻塞工作，把反馈保存在子系统交付记录并提醒用户；不要伪称已经提交 issue。
