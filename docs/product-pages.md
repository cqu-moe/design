# 产品展示与工作界面

先判断用户在页面上要完成什么，再决定用色。产品信息来自现有源码、文档和可核实入口；未核实的版本、资格、功能与源码地址不填占位值。

## 页面用途

```text
用户主要在做什么？
├─ 了解产品、比较价值、寻找安装方式 → 展示页
├─ 登录、授权、首次配置 → 工作界面
└─ 填表、执行操作、管理设置、检查状态 → 工作界面
```

混合页面按区域处理：介绍区可以用蓝色色面，表单区保留中性表面与黑白主按钮。未登录、首屏、首页都不能单独作为使用大面积品牌色的理由。

## 展示页必须准备的信息

| 内容           | 交付要求                                                   |
| -------------- | ---------------------------------------------------------- |
| 产品身份       | 产品名、独立 Logo、所属 CQU Moe、是否学校官方              |
| 用途与适用人群 | 一句话说明解决什么；紧接操作系统、浏览器、资格、网络等限制 |
| 功能亮点       | 来自实际能力；说明行为与边界，不能统一编造“三大卖点”       |
| 使用方式       | 按首次成功使用的顺序写安装、授权、启动步骤；提供真实入口   |
| 演示           | 展示核心操作和结果；合成数据标“交互示例”，不暗示真实提交   |
| 更新与恢复     | 说明更新方式、失败后怎么办，以及是否保留原数据             |
| 数据与权限     | 解释所需权限、处理的数据；链接现有隐私说明                 |
| 资源与支持     | 文档、FAQ、反馈；有公开源码才显示源码地址与已核实的许可证  |

首屏包含身份、用途、关键限制和一个主要开始入口。详细安装步骤放在独立锚点区，顶部导航能直达；核心使用信息不能只藏在 FAQ。

尚无已确认 Logo 时只显示产品名。功能与资源默认用标题、说明和分隔线组织；没有独立交互或分组需要时，不把每项套进等宽卡片。

QuickLogin 当前素材应说明桌面 Chrome、Auth 内测资格和 ZIP 安装；快速评教应说明 Tampermonkey、学校页面与逐门核对。QuickLogin 没有核实公开源码地址，不添加“开源”标签；快速评教可展示已核实的 GitHub 和 MIT。产品条件变化时先复核来源。

评分档位、分数区间、默认值、保存范围和安装 URL 都属于业务合同，必须核对消费源码，不能由设计规范推测。无法核实时通过页面 props 接收已核实的选项与入口，且不预选评分；不要编造“5 分制”“保存成功”或持久化开关。这里的设计演示数据不能成为真实产品默认值。

## 颜色与演示框

- 展示页可以使用品牌实底、浅品牌衬底和品牌主动作；数值与可用范围见 [主题变量](tokens.md)，不要另建产品色。
- 一处操作区只强调一个开始动作；帮助、源码、FAQ 为次要链接。资源数量来自实际内容，不强凑等宽卡片。
- 演示外围最多一层品牌衬底，内部一层中性窗口。使用细分隔线或下划线步骤栏，不叠加大色块、粗边框和重复流程说明。
- 演示输入使用共享控件与至少 16px 字号；不能通过缩小整张截图假装界面可操作。长内容重排或滚动，底部动作可达。
- 工作界面的背景、卡片、导航选中、主按钮、开关保持中性；蓝色只点缀品牌标识、链接和焦点。成功、警告、错误沿用状态色。
- 品牌方向已确认；展示页版式仍在探索，第三版正按用户提供的 Diolen 参考制作。用户确认前，不要把任何现有原型或第三版草稿当作强制模板。

## 按钮与导航的实际用法

动作使用 Button；页面/安装入口使用真实链接，按钮外观用 Button `asChild`。变体、尺寸及默认值的封闭集合见 [组件规则](components.md)。`brand` 变体不存在；展示页通过 CSS 类在按钮所在容器映射语义变量。

```tsx
// 正确：品牌页当前按钮模式；brand-action 只作用于这一入口
<Button asChild className="brand-action">
  <a href="#install">开始安装</a>
</Button>

// 错误：改造同一入口时发明不存在的变体，并把导航变成无行为的按钮
<Button variant="brand">开始安装</Button>
```

1.2.0 消费项目可按 [主题变量](tokens.md) 局部映射品牌主动作。工作界面的主按钮、开关和导航选中态保持中性；未升级到 1.2.0 的项目先升级，不复制 token 定义。

包版本、缺失 token、迁移安排写在交付说明或开发注释中，不在产品页放“API 边界”等实现提示。产品访客只需要影响安装与使用的条件。

```tsx
// 正确：告诉使用者下一步做什么
<p>选择评分，提交前还可以逐门调整。</p>
// 错误：把开发者的数据接入要求展示给使用者
<p>评分档位与默认值由消费仓库核实后传入。</p>
```

## 交付检查

- 展示页与工作界面分别检查 320 / 390 / 768 / 1440 宽度、浅深主题；手机不能隐藏安装条件、核心操作或资源入口。
- 正文和按钮文字对比度至少 4.5:1，大字至少 3:1；检查实际背景，不只比较 token。
- 键盘可访问步骤、输入与资源；触屏目标至少 44 × 44px，输入至少 16px。无悬停依赖，遵循减少动态效果。
- 核对所有安装、文档、支持、源码链接；未发生的真实提交不能显示为成功。
- 原型验证、共享包发布、素材同步和消费产品上线分别记录，不能互相代替。
