# CI/CD

## Policy

- GitHub Actions runs on pull requests, every branch push, `v*` tag pushes, and manual dispatch.
- The stable required result is the **CI result** job. It fails unless source checks and both Chromium gates pass.
- Pull requests run the frozen-dependency source gate plus browser E2E and installed-tarball consumer verification. Every run packages theme/ui so packaging regressions are caught before merge; pushes to `main` retain the tarballs, checksums, and preview `dist` build as candidate Actions artifacts.
- A `v*` tag must point to a commit reachable from `origin/main`, match `packages/theme` and `packages/ui` versions and the template dependency versions, rerun CI, and create an immutable GitHub Release containing the two tarballs and SHA-256 checksums. GitHub never runs `npm publish`.

Main artifacts are uploaded by the source job before browser verification finishes; treat them as candidates until the stable **CI result** job passes.

- Workflow permissions are read-only except the tag-only release job, which needs `contents: write` to create the GitHub Release. Workflows use `pnpm install --frozen-lockfile`, pinned Node `22.22.3`, the package-root `packageManager`, and full-length Action commit SHAs.

## Cloudflare Git Builds

Cloudflare Git Builds remains the production deployer. No Wrangler deploy or build hook is embedded in GitHub Actions.

Configure Cloudflare from this repository root for `main` with:

```sh
pnpm install --frozen-lockfile && pnpm check && pnpm exec playwright install --with-deps chromium && pnpm test:e2e && pnpm verify:consumer
```

`pnpm check` builds theme, UI, and preview, then runs type checking, Vitest, Node distribution tests, and the design-rule scanner. The command then installs Chromium, runs browser E2E, and verifies a relocated consumer installed from the generated tarballs. A failed gate must leave the deployment closed. Because GitHub branch protection is unavailable for this private repository, Cloudflare uses this full command as its own pre-deploy gate rather than relying on **CI result**. This also tests the build under Cloudflare’s actual runtime environment.

## Package and local dependency boundaries

The repository itself uses `workspace:*` links between its own packages. Consumer projects receive relative `.design/*.tgz` files generated by `pnpm create:app`; those files must be committed by the consuming repository, never replaced with an absolute path. GitHub release tarballs are generated from the tagged Git source and lockfile, so CI needs no out-of-repo local tarball. `verify:consumer` intentionally installs its newly generated, not-yet-locked consumer project with `--no-frozen-lockfile`; the source repository install remains frozen.

The release validator checks that theme and UI package versions match the tag and that `templates/app/package.json` depends on those exact versions. The template’s own `version` is the generated app template version (`0.1.0`) and is intentionally independent of the library tag; do not bump it merely to make the CI workflow merge.

Repository settings cannot be changed from this workflow: branch protection currently returns a permissions/plan restriction, so select **CI result** manually when protection becomes available. Until then, do not describe protection as configured.
